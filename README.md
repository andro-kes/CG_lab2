# Лабораторная работа №2: камера и освещение

Надстройка над первой лабораторной, вариант 9 (конус), с реализацией всех пунктов задания на 5. C++20, Vulkan, GLFW и ImGui. Основа окна и Vulkan взята из первой лабы и стартового проекта преподавателя; LICENSE и NOTICE сохранены.

## Сборка и запуск

В текущей папке KG находятся lab1 и lab2. Из PowerShell:

~~~powershell
cd lab2
.\build.cmd --offline
.\run.cmd
~~~

Скрипты используют инструменты из соседней lab1/.tools, а CMake — уже загруженные исходники зависимостей из lab1/build/_deps. Новая сборка располагается в lab2/build, первая лабораторная не изменяется.

Результат успешной сборки — build/lab2.exe и четыре файла build/shaders/*.spv. Для запуска нужны DLL компилятора из PATH, поэтому используйте run.cmd. Требуется драйвер с поддержкой Vulkan.

Если переносите lab2 отдельно, установите инструменты из tools.lock.json в lab2/.tools и запустите build.cmd без --offline: зависимости загрузятся из закреплённых в CMakeLists.txt ревизий. Можно использовать обычный CMake с C++20-компилятором и Vulkan SDK вместо локального preset. Системные переменные среды скрипты не изменяют.

При выборе инструментов приоритет такой: явно заданный `LAB_TOOLS_ROOT`, затем `lab2/.tools`, затем `lab1/.tools`. Сборка, DLL и validation layers используют один выбранный каталог. ## Управление

Разделы панели раскрываются нажатием на заголовок. Параметры можно перетаскивать мышью; Ctrl+щелчок по числу позволяет ввести значение. Для ограниченных полей действует ограничение диапазона.

- **Camera**: положение камеры, повороты по горизонтали и вертикали, проекция и угол обзора. Reset camera возвращает исходный вид.
- **Object and material**: преобразования конуса, Albedo, Specular color и Shininess. Больший Shininess делает блик уже.
- **Multiply by vertex colors**: умножает альбедо на процедурные цвета из первой лабы.
- **Animation**: Play/Pause, Reset motion, скорость и размеры траектории из первой лабы.
- **Ambient and directional light**: параметры общего освещения. Нулевая интенсивность выключает соответствующий вклад.
- **Point lights**: Add point, Remove all points и отдельные настройки каждого источника. Кнопка Remove point находится внутри раскрытого источника.
- **Spotlights**: аналогичные действия для прожекторов. Aim at object направляет прожектор на текущий центр конуса один раз.
- **Show light markers**: показывает или скрывает всю визуализацию источников, сохраняя их освещение.
- **Show spotlight cones**: отдельно управляет линиями прожекторов. Кубики остаются видимыми, если включён общий переключатель.
- **Reset all**: возвращает исходные настройки, количество источников и останавливает анимацию.

Direction задаёт направление распространения света, то есть от источника к сцене. В шейдер передаётся нормализованный вектор. Для нулевого вектора используется направление вниз (0, -1, 0).

Углы прожектора — полууглы от его оси, в градусах. Внутренний угол не превышает внешний. Равные углы дают жёсткую границу, различные — мягкий переход. Белые линии показывают внешний конус, серые — внутренний; длина визуализации фиксирована и не означает границу затухания.

Кубики и линии имеют постоянный цвет: ambient, материал конуса и другие источники на них не влияют. Нулевая интенсивность выключает освещение, но сохраняет маркер, чтобы источник можно было найти.

## Основные вычисления

Все расчёты освещения выполняются в мировых координатах.

1. Положение вершины: world = M * position.
2. Положение на экране: clip = P * V * world.
3. Нормаль: N = normalize(mat3(transpose(inverse(M))) * normal).
4. L — единичное направление от фрагмента к источнику.
5. V — направление к камере; при ортографической проекции оно постоянно и противоположно направлению камеры.
6. H = normalize(L + V) — половинный вектор Блинна—Фонга.
7. Diffuse = albedo * max(dot(N, L), 0).
8. Specular = specularColor * pow(max(dot(N, H), 0), shininess).
9. Вклад источника: (Diffuse + Specular) * lightColor * intensity.

Блик рассчитывается только при положительном dot(N, L), чтобы обратная сторона не давала отражение. Ambient добавляется один раз: albedo * ambientColor * ambientIntensity.

Для точечного источника и прожектора вклад делится на квадрат расстояния. В позиции самого источника расстояние снизу ограничено: max(r², 0.0001). Это предотвращает деление на ноль.

Для прожектора theta = dot(-L, direction). Между двумя углами применяется:

~~~text
coneFactor = clamp((theta - cos(outer)) / (cos(inner) - cos(outer)), 0, 1)
~~~

При равных углах используется отдельная проверка попадания в конус без деления на ноль. Локальные источники складываются с направленным и рассеянным светом. Слишком большая суммарная интенсивность может дать белую пересвеченную поверхность: для демонстрации уменьшите интенсивность.

## Буферы и синхронизация

| Set | Binding | Тип | Содержимое |
| --- | --- | --- | --- |
| 0 | 0 | Uniform buffer, std140 | View-projection, камера, ambient, направленный свет, количество источников |
| 0 | 1 | Storage buffer, std430 | Массив точечных источников |
| 0 | 2 | Storage buffer, std430 | Массив прожекторов |
| 1 | 0 | Uniform buffer, std140 | Матрица модели, матрица нормалей и материал |

Размеры структур: SceneUniform — 160 байт, ModelUniform — 160, PointLightGpu — 32, SpotLightGpu — 64. Поля используют mat4, vec4 и uvec4; static_assert проверяет размеры и смещения.

В GLSL массивы объявлены как lights[] без заданного максимального количества. При нехватке места CPU создаёт больший буфер и обновляет дескриптор. Ограничение — доступная память и maxStorageBufferRange устройства. При удалении всех источников счётчик становится нулевым, но остаётся корректный буфер ненулевого размера.

Одновременно выполняется один кадр. internal::prepare ждёт его fence, после чего можно записывать данные, менять дескрипторы и освобождать заменённые буферы. После записи вызывается vmaFlushAllocation.

Для объекта, кубиков и линий используются три конвейера с общим pipeline layout. Линии рисуются через LINE_LIST с толщиной 1, поэтому дополнительные функции Vulkan для широких линий не требуются.
